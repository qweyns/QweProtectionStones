## 💡 Что это

Игрок ставит блок-ядро — вокруг него появляется защищённая территория. У привата есть **прочность**:
взрывы снимают её по одной единице, а когда она заканчивается — приват падает. Прочность качается
за ресурсы, внутри можно купить постоянные эффекты, а границы подсвечиваются частицами.

**Плагину не нужны внешние плагины защиты.** Собственные клеймы, собственный пространственный индекс,
собственный движок защиты — ставится на голый Paper.

## ⚔️ Возможности

> ### Механика осад
> Взрывы не ломают постройки внутри привата, но снимают прочность с ядра. Есть кулдаун урона
> (стак ТНТ не сносит приват за тик), штраф на цену починки после атаки и уведомления владельцу
> в чат, Discord и Telegram.

> ### Пять уровней доверия
> `ACCESS` → `CONTAINER` → `BUILD` → `MANAGER` → `OWNER`. Друга можно пустить к сундукам,
> не давая ему ломать постройки. В ProtectionStones было только «владелец / участник».

> ### 17 флагов защиты
> PvP, вход, спавн мобов, гриферство мобов, огонь, жидкости, поршни снаружи, вытаптывание грядок,
> телепорт внутрь, подбор предметов и другие. Настраиваются на тип привата в `regions.yml`
> и переопределяются игроком через `/ps flag`.

> ### Анимированные GUI
> Полностью кастомные меню для прокачки и покупки эффектов, покадровая анимация предметов,
> требования на показ и на клик. Экономика через **Vault** или **PlayerPoints**.

> ### Приглашения и чёрные списки
> `/ps invite` шлёт игроку предложение — он сам решает, принимать ли (`/ps accept`, `/ps deny`);
> молчаливого вписывания больше нет. `/ps ban <ник>` закрывает вход конкретному человеку,
> не запрещая его всем сразу флагом `entry`. `/ps trustall` выдаёт доступ во все приваты за раз.

> ### Предпросмотр и поиск места
> Взяли блок-ядро в руку — видите каркас будущей территории и надпись, свободна она или
> перекрывается с чужой. `/ps findspot` сам ищет ближайшую свободную площадку под выбранный тип.

> ### Журнал действий
> `/ps log` показывает, кто и что ломал, ставил и открывал внутри привата. Записи копятся в БД
> пачками и подрезаются по возрасту, так что таблица не растёт бесконечно.

> ### Производительность
> Поиск клейма по координате — O(1) через чанковый индекс. Никаких запросов к внешним плагинам
> на каждое событие. БД пишется асинхронно через пул HikariCP, партиклы кэшируются и ограничены по
> количеству, голограммы выгружаются вместе с чанками, а меню перерисовываются только когда приват
> реально изменился (счётчик версии) — статические предметы берутся из кэша.

> ### Настраивается почти всё
> Звуки (свои для меню, рейда, чужака — с громкостью и высотой, любой можно выключить),
> частицы границ (тип, размер, плотность, потолок точек), 14 таймингов и лимитов,
> требуемый уровень доверия для каждого действия и список флагов, закрытых от игроков.
> Ничего из этого больше не зашито в коде.

> ### Отдельный файл на приваты
> Всё про блоки-ядра живёт в `regions.yml`: размер, прочность, прокачка, флаги, взрывы,
> звуки, голограммы, цвет каркаса, иммунитет к рейдам, своё меню и тексты входа.
> У каждого типа своя цена прокачки и свой предмет оплаты.

> ### Голограммы под контролем
> Для **FancyHolograms** — подложка, выравнивание, прозрачность для блоков, тень на земле,
> яркость, смещение, интерполяция, режим видимости и период обновления. Для
> **DecentHolograms** — радиус и период обновления, точка привязки, право на просмотр.
> Во время осады голограмма показывает отдельный набор строк.

> ### Своё оформление привата
> `/ps name` — название вместо ника в голограмме, меню и на карте. `/ps greeting`
> и `/ps farewell` — собственные тексты при входе и выходе, с цветами и плейсхолдерами.

> ### Folia, карта, бэкапы
> Планировщик абстрагирован, региональные задачи работают на **Folia** тем же jar-ом.
> Границы приватов рисуются на **Dynmap**. `/qps export` выгружает все приваты в JSON,
> `/qps cleanup` удаляет заброшенные.

## ⚡ Установка

**1.** Поместите `QweProtectStones.jar` в папку `plugins`.
**2.** Запустите сервер — сгенерируются `config.yml`, `regions.yml`, `lang/` и `menus/`.
**3.** Настройте типы приватов в `regions.yml`:

```yaml
region_types:
  DIAMOND_BLOCK:
    radius: 8              # территория 17x17 вокруг ядра
    radius_y: 32
    max_per_player: 3
    start_durability: 1
    max_durability: 1
```

Указывать нужно только отличия от `default_region` — всё остальное берётся оттуда.

При обновлении с прежней версии настройки переносятся автоматически: плагин ищет их
сначала в `claims.yml`, затем в `config.yml`, переименовывает секции и складывает
в `regions.yml`. Таблицы базы (`qps_claims` и остальные) переименовываются в `qps_regions`
при первом запуске. Ничего перенастраивать вручную не нужно.

Опционально: **DecentHolograms** или **FancyHolograms** — для голограмм над ядром,
**Vault** / **PlayerPoints** — для оплаты эффектов, **PlaceholderAPI** — для плейсхолдеров,
**Dynmap** — для границ приватов на карте.

### Что стоит посмотреть в `config.yml`

```yaml
settings:
  command:
    name: ps                    # имя игровой команды
    aliases: [приват, region, land, rg]
  region_cooldown_seconds: 3    # антиспам на установку ядер
  preview_borders: true         # каркас будущего привата в руке
  invite_expire_seconds: 120    # сколько живёт приглашение
  abandoned:
    enable: false               # авто-снос приватов неактивных игроков
    inactive_days: 60
    check_interval_minutes: 60
    keep_upgraded: true         # прокачанные не трогать
  action_log:
    enable: true                # журнал /ps log
    log_containers: true
    keep_days: 14               # старше — подрезается

map:
  dynmap:
    enable: true
    layer_name: "Приваты"
    line_color: "#00B4DB"
    fill_opacity: 0.25
```

### Кастомизация

```yaml
sounds:                            # ЗВУК, ЗВУК:громкость или ЗВУК:громкость:высота
  menu_denied: ENTITY_VILLAGER_NO:1.0:1.0
  raid_attack: ENTITY_ENDER_DRAGON_GROWL:1.0:1.0
  raid_nearby: none                # none или off — выключить звук совсем

visuals:
  particle:
    type: DUST                     # цвет учитывается только у DUST
    size: 1.5
    density: 1.0                   # 0.5 плотнее, 2.0 реже и дешевле
    max_points: 2000

trust:                             # какой уровень нужен для каждого действия
  required:
    interact: ACCESS               # двери, кнопки, кровати
    container: CONTAINER           # сундуки и печи
    build: BUILD
    entity: BUILD                  # рамки, стойки брони, вагонетки
    manage: MANAGER
  flag_edit_level: MANAGER
  member_edit_level: MANAGER

flags:
  locked: []                       # флаги, закрытые от игроков: [pvp, entry]

timings:                           # всё, что раньше было константами в коде
  menu_click_cooldown_ms: 300
  delete_confirm_seconds: 30
  effect_refresh_ticks: 40
  siege_window_seconds: 300

limits:
  autoadd_friends: 50
  log_page_size: 15
  findspot_rings: 24
```

Всё перечисленное подхватывается по `/qps reload`. Старые конфиги без этих секций
продолжают работать — недостающие значения берутся по умолчанию.

### Что можно настроить у каждого типа привата (`regions.yml`)

```yaml
default_region:                # значения для всех типов сразу
  radius: 16                   # radius_x / radius_z — для неквадратной территории
  radius_y: 64
  full_height: false           # true — от бедрока до неба

  start_durability: 2
  max_durability: 10
  upgrade:
    item: ""                   # свой предмет оплаты; пусто — общий
    cost_multiplier: -1        # -1 — общее значение
    tax: -1

  raid_immune: false           # приват нельзя повредить взрывом
  damage_cooldown_ticks: -1    # свой кулдаун урона
  explosion_damage_radius: -1  # свой радиус, в котором взрыв достаёт ядро

  menu: ""                     # какое меню открывает клик по ядру
  border_color: ""             # свой цвет каркаса, например "#FF00AA"
  greeting: ""                 # текст входа по умолчанию для типа
  farewell: ""

  hologram_lines: ["<#F0F0F0>Владелец: <#FFaa00>%owner%"]
  hologram_lines_under_attack: ["<#FF5555>⚔ ПОД АТАКОЙ"]

  hologram_settings:
    update_interval: 20        # оба провайдера
    see_through: false
    permission: ""

    shadow: true               # FancyHolograms
    scale: 1.0
    billboard: CENTER
    text_alignment: CENTER
    background: ""             # "#40000000" — полупрозрачная подложка
    visibility: ALL            # ALL, PERMISSION_REQUIRED, MANUAL
    shadow_radius: 0.0
    shadow_strength: 1.0
    interpolation_ticks: 0
    translation: {x: 0.0, y: 0.0, z: 0.0}
    brightness: {block: -1, sky: -1}

    update_range: 48           # DecentHolograms
    down_origin: false
```

В типе достаточно указать только то, что отличается от `default_region`.

**Folia:** отдельная сборка не нужна — тот же jar. Планировщик выбирается автоматически.

## 🎮 Команды

### Для игроков

Имя команды задаётся в `config.yml` (`settings.command.name`, по умолчанию `ps`)
вместе с алиасами — `/приват`, `/region`, `/land`, `/rg`.

| Команда | Описание |
| --- | --- |
| `/ps` | Открыть меню привата, в котором стоите |
| `/ps info` | Карточка привата + подсветка границ |
| `/ps trust <ник> [уровень]` | Выдать доступ (`access`, `container`, `build`, `manager`) |
| `/ps untrust <ник>` | Отозвать доступ |
| `/ps trustall <ник> [уровень]` · `untrustall` | То же сразу во всех своих приватах |
| `/ps invite <ник> [уровень]` | Пригласить — игрок подтверждает сам |
| `/ps accept` · `/ps deny` | Принять или отклонить приглашение |
| `/ps ban <ник>` · `unban` · `banlist` | Чёрный список конкретного привата |
| `/ps members` | Список участников с уровнями |
| `/ps flag [флаг] [значение]` | Просмотр и изменение флагов |
| `/ps list` | Ваши приваты и те, куда вас вписали |
| `/ps home [id]` | Телепорт к привату |
| `/ps log [страница]` | Журнал действий внутри привата |
| `/ps findspot [тип]` | Найти ближайшее свободное место под приват |
| `/ps transfer <ник>` | Передать приват (вы остаётесь управляющим) |
| `/ps delete` | Удалить приват (с подтверждением) |
| `/ps glow` | Постоянная подсветка границ |
| `/ps name <текст>` | Название привата (`clear` — убрать) |
| `/ps greeting <текст>` · `/ps farewell <текст>` | Свои сообщения при входе и выходе |
| `/ps upgrade` · `/ps effects` | Меню прокачки и магазин эффектов |
| `/ps autoadd [ник]` · `autoremove` · `autolist` | Авто-вписывание друзей в новые приваты |
| `/ps help` | Справка по всем подкомандам |

### Для администрации

Отдельная команда с именем плагина — `/qweprotectstones`, алиасы `/qps` и `/qpstones`.
Она объявлена в `plugin.yml` и не зависит от настроек игровой команды.

| Команда | Описание |
| --- | --- |
| `/qps reload` | Перезагрузить конфиги, языки, меню и типы приватов |
| `/qps bypass` | Включить или выключить режим обхода защиты |
| `/qps info [id]` | Полная информация о привате + статистика атак (сколько, когда, кто) |
| `/qps delete [id]` | Удалить любой приват |
| `/qps save` | Немедленно сохранить все приваты в базу |
| `/qps stats` | Количество приватов и загруженных типов |
| `/qps export` | Выгрузить все приваты в `exports/regions_<дата>.json` |
| `/qps cleanup` | Удалить заброшенные приваты прямо сейчас |

### Права

| Право | Назначение |
| --- | --- |
| `qweprotectstones.admin` | Административная команда и служебные флаги |
| `qweprotectstones.bypass` | Возможность включить обход защиты (`/qps bypass`) |
| `qweprotectstones.limit.<тип>.<число>` | Лимит приватов данного типа (берётся максимальное значение) |
| `qweprotectstones.limit.unlimited` | Снимает лимиты полностью |

## 🧩 Плейсхолдеры PlaceholderAPI

| Плейсхолдер | Значение |
| --- | --- |
| `%qps_standing_owner%` | Владелец привата под ногами |
| `%qps_standing_name%` | Название привата (или ник владельца, если названия нет) |
| `%qps_standing_type%` | Тип привата |
| `%qps_standing_size%` | Размер территории |
| `%qps_standing_durability%` · `%qps_standing_max_durability%` | Прочность |
| `%qps_standing_members%` | Число участников |
| `%qps_standing_trust%` | Ваш уровень доступа |
| `%qps_standing_penalty%` | Множитель штрафа (`0`, если штрафа нет) |
| `%qps_standing_siege%` | «Под атакой» или «спокойно» |
| `%qps_standing_attacks%` | Сколько раз приват атаковали |
| `%qps_regions_count%` | Сколько приватов у игрока |
| `%qps_regions_total%` | Всего приватов на сервере |

## 🔌 API для разработчиков

События (`org.qweyns.qweprotectstones.regions.event`), все отменяемые:

```java
@EventHandler
public void onRegionCreate(RegionCreateEvent event) {
    Region region = event.getRegion();
    if (region.getBounds().area() > 10_000) event.setCancelled(true);
}
```

- `RegionCreateEvent` — перед созданием привата
- `RegionDeleteEvent` — перед удалением (`Reason`: BROKEN, DESTROYED_BY_RAID, COMMAND, ADMIN, EXPIRED)
- `RegionDamageEvent` — перед снятием прочности, можно изменить урон

Прямой доступ: `((QweProtectStones) Bukkit.getPluginManager().getPlugin("QweProtectStones")).getRegionAt(location)`

## 🔨 Сборка

```bash
mvn clean package
```

Готовый `QweProtectStones-<версия>.jar` появится в `target/`. HikariCP упаковывается внутрь jar
с переносом пакета, остальные зависимости берутся с сервера.

Юнит-тесты (`mvn test`) покрывают доменный слой — границы, чанковый индекс, уровни доверия,
флаги, расчёт цены прокачки и нормализацию пользовательских текстов. Эти классы намеренно
не зависят от Bukkit, поэтому проверяются без запуска сервера: 55 тестов.

## ⚠️ Переход с прежней версии

Плагин переименован из `PSHologramm`, поэтому меняются три вещи:

- папка данных: `plugins/PSHologramm/` → `plugins/QweProtectStones/`
- префикс таблиц по умолчанию: `psholo_` → `qps_`
- права: `pshologramm.*` → `qweprotectstones.*`

Если у вас уже была рабочая база от прежней сборки — перенесите папку и верните
старый префикс в `config.yml`:

```yaml
database:
  table_prefix: "psholo_"
```
