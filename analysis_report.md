TrustLevel is deeply rooted in the DB as a VARCHAR(16) string inside `region_members` table. It's an Enum with ACCESS, CONTAINER, BUILD, MANAGER, OWNER. We need to introduce Custom Roles. We'll change `TrustLevel` to a `Role` object fetched from Config, or keep `TrustLevel` as a fallback string ID. `ProtectionService` resolves Trusts. MenuRequirements checks Trusts. AutoAdd and Invites hardcode TrustLevel.BUILD/ACCESS. Database migrations aren't strictly necessary if we just store the Role ID (e.g. 'builder') instead of 'BUILD', as it's just a VARCHAR.
