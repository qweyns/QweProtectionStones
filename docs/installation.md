# Установка

## Требования

- Сервер **Paper 1.21+** (или Folia — отдельная сборка не нужна).
- **Java 21+**.

## Первая установка

1. Положите `QweProtectStones.jar` в папку `plugins/`.
2. Запустите сервер — создастся папка `plugins/QweProtectStones/` с конфигами.
3. Настройте типы приватов в `regions.yml` (минимум — размеры и прочность).
4. `/qps reload` — и можно ставить блок-ядро.

При первом запуске на **SQLite** ничего настраивать не нужно — база создастся
рядом с конфигами. Для **MySQL** заполните секцию `database` в `config.yml`
и перезапустите сервер (настройки базы читаются только при старте).

## Структура папки

```
plugins/QweProtectStones/
├── config.yml       — база, команда, лимиты, тайминги, доверие
├── protection.yml   — движок защиты: воронки, граница, locked-флаги
├── siege.yml        — осады
├── effects.yml      — эффекты и их покупка
├── visuals.yml      — частицы, звуки, карты
├── features.yml     — рынок, аренда, границы, бэкапы, импорт
├── regions.yml      — типы приватов
├── menus/           — GUI: main, upgrade, effects
├── lang/            — локализации (ru_RU, en_US, es_ES, zh_CN)
└── exports/         — JSON-выгрузки (/qps export, бэкапы)
```

## Обновление

Замените jar и перезапустите сервер. Плагин сам:

- перенесёт настройки из старого единого `config.yml` (и совсем старого
  `claims.yml`) в новые файлы;
- переименует таблицы базы (`qps_claims` → `qps_regions` и остальные) —
  данные сохраняются;
- добавит отсутствующие ключи со значениями по умолчанию.

Старые ключи не удаляются и не мешают. После обновления загляните в новые
конфиги — часть настроек могла переехать в более подходящий файл.

## Миграция с PSHologramm

Плагин переименован, меняются три вещи:

- папка данных: `plugins/PSHologramm/` → `plugins/QweProtectStones/`;
- префикс таблиц: `psholo_` → `qps_`;
- права: `pshologramm.*` → `qweprotectstones.*`.

Перенесите папку плагина и верните старый префикс:

```yaml
database:
  table_prefix: "psholo_"
```

## Несколько серверов (сеть)

Плагин держит приваты в памяти и пишет их в базу пачками — это быстро
на одном сервере, но означает, что **одна база обслуживает один сервер**.
Два сервера, подключённые к общей MySQL-базе, не будут видеть правки
друг друга и со временем перезапишут их (последняя запись побеждает).

Для сети серверов у каждого сервера должна быть своя база: либо локальная
SQLite (значение по умолчанию), либо отдельная база MySQL на каждый сервер
(разные значения `database.database` при общем сервере MySQL).

## Перенос приватов из других плагинов

См. [Импорт](integrations.md#import) — WorldGuard, ProtectionStones
и GriefPrevention читаются напрямую из их файлов, сами плагины ставить не нужно.
