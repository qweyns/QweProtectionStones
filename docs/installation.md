## Требования и запуск

- Java 21; сборка использует Paper API 1.21.4. Совместимость с другими версиями проверяйте на стенде.
- Для Folia отдельный JAR не нужен, но обязательно тестирование с набором плагинов сервера.
- WorldGuard/ProtectionStones не обязательны; для рынка нужен Vault **и** провайдер экономики.

Положите JAR в `plugins/`, запустите сервер, настройте `regions.yml` и выполните
`/qps reload`. SQLite создаёт `data.db` автоматически. Для MySQL заполните
`database` в `config.yml` и перезапустите сервер.

Файлы настроек описаны в [конфигурации](configuration.md). Дополнительно:

| Путь в папке QweProtectStones | Назначение |
|---|---|
| `data.db` и SQLite WAL/SHM | Локальная БД; не копируйте только основной файл при активной записи |
| `logs/critical.log` | Файловый журнал критических операций (настраивается) |
| `exports/` | Ручные JSON-выгрузки |
| `backups/` | Автоматические/внеплановые JSON-копии с ротацией |
| `storage-recovery.yml` | Неподтверждённые SQL-операции для восстановления |

## Обновление

1. Остановите сервер и сохраните всю папку плагина и согласованную копию БД.
2. Замените JAR. Сравните свои файлы с [встроенными ресурсами](../src/main/resources).
3. Запустите сервер, проверьте загрузку типов, регионов, экономики и отсутствие SQL-ошибок.

Общие настройки объединяются из шести файлов: config, protection, siege, effects,
visuals, features. Пропущенные общие ключи берутся из JAR **в памяти**, а не дописываются
в пользовательский файл. `regions.yml` использует свои `default_region` и `region_types`;
новые типы/рецепты туда автоматически не добавляются. Существующие меню также не заменяются.
Переводы дополняются встроенным выбранным языком (или en_US, если такого языка в JAR нет).

Только при отсутствии `regions.yml` возможен перенос секций типов из `claims.yml`,
затем из старого `config.yml`. Это не универсальная миграция всех старых настроек:
проверьте разделение остальных секций вручную. При одинаковых верхнеуровневых секциях
в нескольких файлах поздний файл перекрывает ранний; в консоли появляется предупреждение.
Порядок файлов указан выше. SQL-схема мигрирует при запуске; резервная копия обязательна.

При переходе с PSHologramm перенесите папку данных, сохраните прежний
`database.table_prefix` (например `psholo_`) и обновите права на `qweprotectstones.*`.

## Reload и Folia

`/qps reload` перечитывает настройки, язык, меню, типы и перезапускает основные таймеры.
Команда/алиасы, параметры БД, connect timeout HTTP-клиентов и состав установленных
интеграций требуют рестарта. bStats/PAPI регистрируются при запуске.

На Folia используется NATIVE. DH/FH работают только на Paper. Горячий unload
и серверный `/reload` не поддерживаются: требуется полный restart. При shutdown
плагин не трогает сущности чужого потока; непостоянные NATIVE-дисплеи не записываются в мир.

## Хранение и восстановление

Одна БД обслуживает один сервер: шины синхронизации нескольких инстансов нет.
Изменения записываются пакетами. После ошибки подтверждаются только успешные операции,
остальные повторяются и при flush сохраняются в `storage-recovery.yml`.
При старте журнал применяется **до загрузки регионов**. Не удаляйте его вручную:
он может содержать удаления, без которых старые приваты вернутся из БД.

Если replay не выполнен, QPS не запускает защиту. Исправьте БД/диск и перезапустите
сервер; не пускайте игроков на сервер без работающей защиты.
Журнал не заменяет backup и не делает каждое действие crash-durable: обрыв питания
до flush, отказ диска и сбой Vault остаются отдельными рисками.
После неоднозначного ответа БД replay может повторить строку журнала действий,
но не воспроизводит экономические платежи. Ошибки компенсации денег требуют ручной проверки.
JSON-export содержит регионы, а не полную копию экономики/БД/настроек.

## Проверка перед production

CI проверяет компиляцию, JUnit, YAML, локализации и shading, не игровую среду.
На копии сервера проверьте:
- создание/снятие ядра и отмену событий сторонним плагином до MONITOR;
- продажу, аренду, возврат при отказе оплаты, отключение экономики;
- осаду: disabled, иммунитет, cooldown, veto смертельного удаления, взрывы аддона;
- двойные сундуки/воронки, поршни, рост растений, зелья и TNT;
- вход/выход во время загрузки autoadd и телепорта;
- на Folia — удалённые регионы, переход между ними, unload чанков и полный shutdown;
- восстановление БД после временного отказа, backup/restore с вашими типами и мирами.
