# QPS: API для аддона кастомных динамитов (механика HolyWorld)

Этот документ — готовое ТЗ для плагина-аддона **QweTnts** «кастомные
динамиты» поверх QweProtectStones (QPS). Все описанные здесь хуки **уже
реализованы в QPS** и покрыты CI. Аддон — отдельный плагин в отдельном
репозитории: github.com/qweyns/QweTnts (уже создан, пустой).

Референсы механики: вики HolyWorld (разделы «Приваты», «Динамит») и открытый
плагин SunTNT (github.com/7byLoper/SunTNT) — разбор обоих в §1.5.

---

## 1. Что копируем с HolyWorld (режим Лайт-Анархия)

### Динамиты

| Динамит | Радиус взрыва | Особенности |
|---|---|---|
| Обычный | ванильный | ванильная ТНТ |
| Динамит A | ×3 от обычного | урон осаде с ×3 дистанции; крафт: 5 пороха + 2 песка + 2 ТНТ; фитиль 5 сек |
| Динамит B | ×10 от обычного | урон осаде с ×10 дистанции; крафт: 5 пороха + 2 песка + 2 динамита A |
| С4 | как обычный | ломает обсидиан/плачущий обсидиан; вредит незерит-привату; **запоминает взорванные блоки → рейд-блок 5 мин** |
| Разрывная волна | как обычный | ломает обсидиан; **плачущий обсидиан взрывает сразу, а древние обломки превращает в обычный обсидиан**; работает в воде и лаве (уничтожая их); сносит **2** прочности привата; **рейд-блок 5 мин** |

Рейд-блок (по зимнему трейлеру вайпа HW Lite): С4 и волна запоминают
**позиции** взорванных блоков — 5 минут на этих местах никто не может
ставить обсидиан, плачущий обсидиан и древние обломки. Загрифили платформу —
5 минут на её месте не строят, и перезаприватить снесённое место сразу
тоже нельзя. Детали реализации — §5.3.

### Типы приватов и стойкость к взрывам

| Приват | Размер | Прочность | Чем взрывается |
|---|---|---|---|
| Железный блок | 5×5 | 1 | любой динамит |
| Золотой блок | 7×7 | 1 | любой динамит |
| Алмазный блок | 11×11 | 1 | любой динамит |
| Изумрудная руда | 21×21 | 1 | любой динамит |
| Незеритовый блок | 31×31 | 1 → 2 (апгрейд незеритовыми слитками) | только С4 и Разрывная волна |
| Уникальный (Древние обломки) | 31×31 | от 4 | только С4 и Разрывная волна |

## 1.5. Референс SunTNT: что берём, что уже покрыто QPS

SunTNT (github.com/7byLoper/SunTNT, Gradle, MC 1.16–1.19, требует SunCore) —
ближайший открытый аналог «динамитов HolyWorld». Идеи и формат настроек
полезные, но осадной интеграции в нём нет: `break-ps-region: true` — просто
бит «уменьшать прочность ProtectionStones», без типов взрывов, атакующего,
кулдауна и урона кратного 2. Маппинг возможностей:

| Возможность SunTNT | Как у нас |
|---|---|
| `explosive-mode: vanilla/ball/cube`, `explosive-power` | аддон: `TNTPrimed.setYield()` или ручная зачистка сферы/куба |
| `cut-damage` (−% урона сущностям) | аддон: `EntityDamageEvent` c `DamageCause.ENTITY_EXPLOSION/BLOCK_EXPLOSION` |
| `explosive-interval` (фитиль, сек) | `TNTPrimed.setFuseTicks()` |
| `auto-ignite` после установки | аддон: `BlockPlaceEvent` → поджиг сразу |
| `water-chance` (взрыв в воде) | аддон: проверка жидкости при активации |
| `break-ps-region` (bool) | **не нужно**: QPS сам снимает прочность по правилам `explosions` с атрибуцией атакующего и кулдауном — аддон только классифицирует взрыв (§3.1) |
| `breakable-blocks: {материал: {radius, chance, drop-chance}}` | аддон: добавление в `blockList()` с проверкой флагов QPS — §5.2, обязательное правило |
| `transformable-blocks: {материал: {radius, to}}` (цепочка сланец → плачущий обсидиан → обсидиан → воздух) | аддон: деградация обсидиана + «рейд-блок» 5 минут как на HW |
| `spawner: {chance, mob-save-chance, gold-chance, mysterious-chance}` | аддон: спавнер в `blockList()` → шанс дропа своего предмета |
| `ice: {enabled, radius, delay}` — временный лёд после взрыва | аддон: `setType(ICE)` + отложенный откат (не в чужих приватах!) |
| руны (автоподжиг, гравитация, восход, эффекты) | аддон, фаза 2 — PDC-тег на предмете ТНТ |
| ТНТ-пушка (`/tnt tntgun`) | аддон, фаза 2 — снаряд-`TNTPrimed` летит по `setVelocity` |
| WG-флаги `cancel-nearby-explosion`, `tnt-block-explosion` | **не нужно**: в QPS уже есть флаг `explosion_damage` (блоки) + правила `explosions` (прочность) |
| `custom_name` над ТНТ-сущностью | `TNTPrimed.setCustomName/setVisible` |
| `/tnt give`, `customitems add/remove` | свой каркас команд по образцу команд QPS |

Чего в SunTNT нет совсем (и что уже готово в QPS): осада с **типами взрывов**
и прочностью приватов (незерит — только С4/волна), урон кратный 2 у волны,
атрибуция атакующего (у нас — поджигавший из `TNTPrimed.getSource()`),
кулдаун урона, Folia, Paper 1.21.4, локализация на 4 языках.

> **Лицензия**: у SunTNT нет файла LICENSE — все права сохранены за автором.
> Код не копируем; берём только идеи и терминологию настроек (формат YAML
> сам по себе не охраняется, но пишем свою схему и свои тексты).

## 2. Архитектура аддона

- Отдельный плагин, `plugin.yml`:

```yaml
name: QweTnts
version: 1.0.0
main: ru.qweyns.qwetnts.QweTnts
api-version: '1.21'
depend: [QweProtectStones]
```

- Динамиты аддон спавнит как `TNTPrimed` с PDC-меткой типа (пример ниже).
- Вся осадная механика (прочность, кулдаун, алерты, уничтожение) уже в QPS —
  аддон только **классифицирует** свои взрывы и при необходимости **модифицирует урон**.
- QPS сам разрулит блоки: флаг привата `explosion_damage` решает, ломать ли
  блоки внутри; правила `explosions` у типа привата решают, снимать ли прочность.

## 3. Точки интеграции (всё уже в QPS)

### 3.1. RegionExplosionTypeEvent — классификация взрыва

`org.qweyns.qweprotectstones.regions.event.RegionExplosionTypeEvent`

Летит, когда взрыв задел чей-то приват и осада включена. Аддон подменяет тип
взрыва — эта строка сверяется с секцией `explosions` у типа привата
(регистр не важен). Заодно можно задать множитель радиуса урона ядру.

```java
public class DynamiteClassifier implements Listener {
    private final NamespacedKey kindKey; // new NamespacedKey(plugin, "dynamite-kind")

    @EventHandler
    public void onClassify(RegionExplosionTypeEvent event) {
        if (!(event.getEntity() instanceof TNTPrimed tnt)) return;
        String kind = tnt.getPersistentDataContainer().get(kindKey, PersistentDataType.STRING);
        if (kind == null) return; // ванильная ТНТ — тип TNT по умолчанию

        switch (kind) {
            case "A" -> { event.setExplosionType("DYNAMITE_A"); event.setDamageRadiusMultiplier(3.0); }
            case "B" -> { event.setExplosionType("DYNAMITE_B"); event.setDamageRadiusMultiplier(10.0); }
            case "C4" -> event.setExplosionType("C4");
            case "SHOCKWAVE" -> event.setExplosionType("SHOCKWAVE");
        }
    }
}
```

- `getEntity()` / `getBlock()` — источник взрыва (один из них null).
- `getDefaultType()` — что QPS определил сам: `TNT, CREEPER, WITHER,
  ENDER_CRYSTAL, BED, WIND_CHARGE`.
- `setDamageRadiusMultiplier(double)` — во сколько раз дальше от ядра
  взрыв ещё снимает прочность (база: `siege.explosion_damage_radius` или
  `explosion_damage_radius` у типа привата). A = 3.0, B = 10.0, остальное 1.0.

### 3.2. RegionDamageEvent — изменение/отмена урона осаде

`org.qweyns.qweprotectstones.regions.event.RegionDamageEvent`

Летит при каждом снятии прочности (взрывом QPS или ручным вызовом API).

- `setDamage(int)` — «Разрывная волна сносит 2»:

```java
@EventHandler
public void onRegionDamage(RegionDamageEvent event) {
    if ("SHOCKWAVE".equals(event.getExplosionType())) {
        event.setDamage(2); // HolyWorld: волна сносит сразу 2 прочности
    }
}
```

- `getAttackerName()` — кто атакует (может быть null); `setCancelled(true)` —
  полностью защитить приват.

### 3.3. QpsApi — программное снятие прочности и справка

```java
QpsApi api = QpsApi.get();               // null, если QPS выключен
api.isAvailable();                       // проверка без get()

// Снять прочность напрямую — полный конвейер QPS (кулдаун, событие,
// алерты, индикатор, голограмма, уничтожение на нуле). Поток сервера.
api.damageRegion(region, 2, "SHOCKWAVE", attacker.getName());

// Справка: вредит ли тип взрыва этому привату (explosions + raid_immune)
api.isExplosionDamaging(region, "C4");

// Кулдаун урона привата (мс; 0 — урон пройдёт)
api.getSiegeService().cooldownRemainingMs(region);

// Включена ли осада (siege.enabled) — без неё урона осаде не будет вообще
api.isSiegeEnabled();

// Типы приватов (радиусы, прочность, правила взрывов)
api.getRegionType("netherite");
api.regionTypeOf(region);
api.getRegionTypes();

// Геометрия и доступ — было и раньше
api.getRegionAt(loc); api.getRegionsOf(uuid); api.isUnderSiege(region);
```

### 3.4. Остальные события

- `RegionDeleteEvent` (`Reason.DESTROYED_BY_RAID`) — приват взорван; аддон
  может, например, логировать или выдавать трофеи.
- `RegionCreateEvent`, `RegionFlagChangeEvent`, `RegionTransferEvent` — общий список.

## 4. Конфиг QPS под механику HolyWorld

### 4.1. Типы приватов (regions.yml)

Незеритовый приват — «только С4 и Разрывная волна», прочность 1, апгрейд до 2:

```yaml
netherite:
  material: NETHERITE_BLOCK
  display_name: "Незеритовый приват"
  radius_x: 15
  radius_y: 15
  radius_z: 15
  start_durability: 1
  max_durability: 2                 # апгрейд незеритовыми слитками до 2
  upgrade_item: NETHERITE_INGOT
  explosions:
    TNT: false                      # ванильная ТНТ и динамит A/B не вредят
    DYNAMITE_A: false
    DYNAMITE_B: false
    C4: true
    SHOCKWAVE: true
```

Уникальный приват — прочность от 4:

```yaml
unique:
  material: REINFORCED_DEEPSLATE   # «Древние обломки»
  radius_x: 15
  radius_y: 15
  radius_z: 15
  start_durability: 4
  explosions:
    C4: true
    SHOCKWAVE: true
```

Дешёвые приваты — «любой динамит», прочность 1:

```yaml
iron:
  material: IRON_BLOCK
  radius_x: 2   # 5×5
  start_durability: 1
  explosions:
    TNT: true
    DYNAMITE_A: true
    DYNAMITE_B: true
    C4: true
    SHOCKWAVE: true
```

Радиусы: 5×5 → `radius_x: 2`, 7×7 → 3, 11×11 → 5, 21×21 → 10, 31×31 → 15.

Ключи в `explosions` — произвольные строки (кастомные типы аддонов
загружаются из конфига без ограничений, регистр не важен).

### 4.2. Осада (config.yml / siege-настройки)

- `siege.enabled: true` — без этого урон осаде не снимается вовсе.
- `siege.damage_cooldown_ticks` — кулдаун между снятиями прочности у одного
  привата; у типа привата можно переопределить (`damage_cooldown_ticks`).
- `siege.explosion_damage_radius` — базовый «радиус до ядра», который
  умножается на `damageRadiusMultiplier` из события классификации.

## 5. Каркас аддона (что писать)

1. **DynamiteType** — record: id, ItemStack-предмет (имя/лore/glow), fuse-тики,
   yield (мощность взрыва блоков), тип для QPS (`DYNAMITE_A`...), множитель
   радиуса, флаги (works-in-water, breaks-obsidian), рецепт.
2. **DynamiteRegistry** — типы из конфига аддона (по образцу RegionTypeRegistry QPS).
3. **Активация** — слушатель `PlayerInteractEvent` (правый клик предметом):
   расходуем предмет, спавним `TNTPrimed` c PDC-меткой типа, `setFuseTicks`,
   `setYield(yield)`, источник — игрок (для атрибуции атак: QPS сам возьмёт
   `TNTPrimed.getSource()` как атакующего).
4. **DynamiteClassifier** — см. §3.1.
5. **Взрыв блоков** — `EntityExplodeEvent` (.MONITOR или HIGHEST):
   - С4/волна: добавить обсидиан/плачущий обсидиан в `blockList()`
     (и убрать воду/лаву из списка для волны — вернее, добавить блоки под ними);
   - волна: пометить сломанный обсидиан «рейд-блоком» на 5 минут (PDC блока
     или карта в аддоне; при попытке поставить — отмена с сообщением).
   Важно: НЕ удалять блоки, если QPS отменил взрыв (проверяйте `event.isCancelled()`),
   внутри чужих приватов блоки защищает флаг `explosion_damage` — QPS сам
   вычищает защищённые блоки из `blockList()` на приоритете LOW.
6. **Крафты** — `ShapedRecipe` с PDC-тегом на результате (чтобы крафт не
   конфликтовал с ванилью, и предмет было видно в конфиге QPS-ядер не нужен).
7. **Проверка «вредит ли»** перед активацией не обязательна — QPS сам решит
   по правилам `explosions`; аддону это нужно только для подсказок в лоре.

### 5.1. Рекомендуемая схема конфига динамита

Один YAML-файл на динамит в `dynamites/` аддона (как `tnts/*.yml` у SunTNT —
админам привычно, а нам удобно грузить как типы QPS). Пример «Разрывной волны»:

```yaml
# dynamites/shockwave.yml
name: shockwave
display_name: "Разрывная волна"

# Ключ в секции explosions у типов приватов QPS (регистр не важен)
explosion-type: SHOCKWAVE
# Множитель радиуса урона ядру (A = 3.0, B = 10.0, у волны 1.0)
radius-multiplier: 1.0
# Базовый урон прочности; слушатель RegionDamageEvent может скорректировать
siege-damage: 2

fuse-seconds: 4          # фитиль
power: 4                 # yield взрыва (радиус блоков как у ванильной ТНТ)
mode: vanilla            # vanilla | ball | cube
cut-entity-damage: 0     # % снижения урона сущностям
works-in-water: true     # взрывается в воде, уничтожая её
works-in-lava: true

# Блоки, которые этот динамит ломает вопреки взрывостойкости
breakable-blocks:
  OBSIDIAN:        { chance: 100, drop-chance: 0 }
  WEEPING_OBSIDIAN: { chance: 100, drop-chance: 0 }
  WATER:           { chance: 100, drop-chance: 0 }
  LAVA:            { chance: 100, drop-chance: 0 }

# Рейд-блок на место сломанного обсидиана (HW: 5 минут нельзя строить)
raid-block:
  enabled: true
  duration-seconds: 300

item:
  material: TNT
  display_name: "&bРазрывная волна"
  lore:
    - ""
    - "&8 • &fРадиус как у обычного динамита."
    - "&8 • &fЛомает обсидиан и работает в воде."
    - "&8 • &fСносит &b2 прочности&f привата."
  glow: true

recipe:
  shape: "GSG:GTG:GSG"
  ingredients: { G: GUNPOWDER, S: SAND, T: TNT }
```

### 5.2. Добавление блоков в blockList() — обязательное правило

QPS фильтрует `blockList()` на приоритете **LOW**: вычищает ядра приватов
и блоки внутри приватов с `explosion_damage: false`. Ваш слушатель на
**HIGH** (после QPS) добавляет обсидиан/жидкости в список — фильтр QPS эти
блоки уже не увидит. Поэтому перед добавлением каждого блока проверяйте сами:

```java
Region region = api.getRegionAt(block.getLocation());
if (region != null && (region.isCore(block.getLocation())
        || !api.flagAt(block.getLocation(), RegionFlag.EXPLOSION_DAMAGE))) {
    continue; // ядро или приват со строгим флагом — блок не добавляем
}
event.blockList().add(block);
```

Без этой проверки С4 будет вырезать обсидиан из чужих приватов в обход
флага — то есть дюпать «бесплатное» проникновение, минуя всю осаду.
Ручные правки блоков (трансформация обсидиана, временный лёд) — та же
проверка; `isTrusted` не нужен, у взрыва нет игрока, решение только по флагу.
Не забыть: слушатель `ignoreCancelled = true`, чтобы не работать после
отменённых взрывов.

### 5.3. Рейд-блок и деградация блоков (зимний трейлер вайпа HW Lite)

Механики из трейлера, которых нет в вики HW:

**Рейд-блок на позициях взорванных блоков.** С4 и Разрывная волна после
взрыва оставляют на месте каждого уничтоженного блока метку на 5 минут:
установка обсидиана, плачущего обсидиана и древних обломков в эти позиции
запрещена всем, включая владельца разрушенного.

Реализация:

- хранение: `Map<мир, Map<позиция, millis окончания>>` в памяти **плюс
  сериализация в файл аддона** — 5 минут реального времени обязаны
  переживать рестарт сервера; чистка по expiry при загрузке и таймером;
- запрет: слушатель `BlockPlaceEvent` с приоритетом **LOWEST** — ядро
  привата QPS ставит на приоритете **HIGH**, отмена раньше не даст
  перезаприватить место сноса «древними обломками» (анти-феникс):

```java
@EventHandler(priority = EventPriority.LOWEST) // раньше QPS (HIGH)
public void onPlace(BlockPlaceEvent event) {
    if (!raidBlockFamily.contains(event.getBlock().getType())) return;
    long until = raidBlocks.expiresAt(event.getBlock().getLocation());
    if (until > System.currentTimeMillis()) {
        event.setCancelled(true);
        event.getPlayer().sendMessage(raidBlockedMessage(until));
    }
}
```

**Деградация блоков по тирам (Разрывная волна):**

| Блок | Результат взрыва волной |
|---|---|
| обсидиан | уничтожается (рейд-блок) |
| плачущий обсидиан | уничтожается сразу (рейд-блок) |
| древние обломки (не ядро!) | превращается в обычный обсидиан |

Трансформация древних обломков — не через `blockList()` (блок должен
**остаться**, но стать обсидианом): слушатель на HIGH после проверки §5.2
делает `block.setType(OBSIDIAN)` вместо удаления. Обсидиан на его месте
снесёт уже следующий взрыв — двухступенчатая деградация, как на HW.

**Критично:** древние обломки — это же материал уникального привата.
Ядро привата нельзя ни взрывать, ни деградировать: проверка
`region.isCore(location)` из §5.2 обязательна и для `blockList()`, и для
трансформации — иначе волна «взорвёт» ядро уникального привата в обход
осады (его легальный путь — прочность 4 → 0 → `DESTROYED_BY_RAID`).

## 6. Замечания

- **Folia**: QPS весь шедулинг гоняет через свой мост; аддону достаточно
  пользоваться обычными Bukkit-событиями (они синхронны в регионе сущности)
  и не трогать блоки из async-потоков.
- **Атрибуция атак**: QPS записывает атакующим поджигавшего
  (`TNTPrimed.getSource()`), а если источник не игрок — ближайшего
  постороннего игрока рядом с ядром. Владельцы и участники привата
  атакующими не считаются.
- **Кулдаун урона** общий на приват (не на тип динамита): залпом из 5 ТНТ
  нельзя снять 5 прочностей — как на HolyWorld.
- **Уничтожение привата** на нуле прочности проходит через RegionDeleteEvent
  (Reason.DESTROYED_BY_RAID) — другие плагины могут отреагировать.
- Защита блоков и урон осаде — независимые вещи: `explosion_damage: false`
  в приват не впускает взрыв блоков, `explosions.TNT: false` запрещает
  снимать прочность. У HolyWorld дешёвые приваты ломаются «с одного
  динамита» — это прочность 1 + разрешённые типы взрывов.
- **Порядок приоритетов `EntityExplodeEvent`**: QPS — LOW (фильтр блоков),
  аддон — HIGH (свои `breakable-blocks` + §5.2), классификация взрыва
  (`RegionExplosionTypeEvent`) летит позже, уже после фильтра.
- Ядро привата взрывом не ломается никогда: QPS сам вычищает его из
  `blockList()`, уничтожение идёт только через осаду (прочность → 0 →
  `RegionDeleteEvent` с причиной `DESTROYED_BY_RAID`).

## 7. Чего ещё не хватает интересного (идеи для QweTnts)

**Фаза 1 — ядро:**

- **Анти-лаг**: лимит одновременно горящих ТНТ на чанк и на игрока;
  крупные взрывы (куб/сфера 25+) очередями по N блоков за тик — одним
  тиком такой объём кладёт сервер в фриз.
- **Кулдаун активации** динамита на игрока — по образцу RegionRateLimiter
  в QPS, защита от спама B-динамитами.
- **Ограничения миров/зон**: запрет взрывов в спавн-мире и радиусе от
  спавна, чёрные списки миров — паттерн `allowedWorlds` у типов QPS.
- **Статистика взрывов**: кто/чем/сколько — для админки и лидерборда
  гриферов; пишется в файл по образцу CriticalFileLogger QPS.
- **Шансы дропа** блоков после взрыва (`drop-chance`) — чтобы сфера из
  обсидиана не превращалась в гору бесплатного лута (анти-дюп).

**Фаза 2 — расширения:**

- **Спавнер-майнинг**: шанс, что спавнер под взрывом выпадет предметом
  с сохранённым мобом (механика HW/SunTNT).
- **Временный лёд**: сфера льда после взрыва, исчезающая через N тиков.
- **Направленный (кумулятивный) заряд**: разрушение конусом в сторону
  взгляда — вскрывать стены, а не гридить площадно.
- **Цепная детонация**: подрыв детонирует лежащие рядом динамиты того же
  типа с задержкой 2–3 тика.
- **Руны** на предмет ТНТ (автоподжиг, гравитация, эффекты) и
  **ТНТ-пушка** — концепты SunTNT, §1.5.
- **Discord-алерты**: взрыв уникального/незерит-привата → уведомление в
  Discord через DiscordSRV (у QPS алерты идут только владельцу в игру).
- **Маркеры взрывов** на Dynmap/BlueMap с таймером рейд-блока — видно,
  где идёт война и сколько висит запрет стройки.
- **Экономика**: продажа динамитов за Vault-деньги / очки PlayerPoints —
  у QPS уже есть оба хука, аддону проще повторить паттерн MenuActions.
